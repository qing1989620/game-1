# V6.4.1 轻量操作引导：验收与代码自审

状态：通过

日期：2026-10-25，Asia/Shanghai。基线：`6d04064`。本轮响应“玩家玩不明白，稍微增加引导”，在五城现有流程上补充操作指引；第五城十关和其余城市的规则、难度、天气与通行机制沿用已验收基线。

## 变化

- 透明任务区常驻下一步：远处解释菱形与距离，靠近设备后提示Q扫描、E工作台，已取证则进入编辑；四步条标明当前步骤。
- 扫描、互动、摇杆、沙漠天气或偏振镜使用静态描边提示，无强制教学弹窗和等待计时。暂停、对话、编辑、演出和结算期间隐藏场景提示。
- 五种工作台加入实际按钮名称的提交说明与“看本关提示”；线索留在面板内，可继续点按深入。不同关卡清除上一关的说明，支线提示以正在检查的关卡为准。
- 手机措辞改成摇杆、溯源和点按；修复流程使用“走近→溯源→交互→验证”，避免只显示键盘键名。
- 首关预演成功文案明确“尚未提交”，提示返回草案再完整验证；不再将预演描述为已经展开通道。

## 验证范围与结果

本轮是实现者的代码自审和浏览器界面验收，不是独立玩家测试或手机硬件认证。

- 自动化：`npm run verify`通过，243项规则/存档/运动测试、严格TypeScript、生产构建及228个本地文档链接检查通过；未为可逆的提示样式编写重复实现的单元测试。`npm audit --json`为0项已知漏洞，`git diff --check`通过。
- 正常UI：28项受影响检查，记录于 [v6.4.1-guide-ui-checks.json](../../artifacts/v6.4.1-guide-ui-checks.json)。三个测试页最终控制台错误均为0。使用1280×720与390×844视口，未调用隐藏运行时、注入存档或开发传送。
- 首城：从新开局正常走到MIRA，完成对话、扫描、编辑、逐级线索、预演与真实验证；任务仅在完整验证后进入DS-01。手机实际按住摇杆走到人物，再点扫描和互动打开Q-01。
- 第二至第四城：用正常城际地图进入、走到NPC和首个设备，分别打开天气、锁序和天线工作台；确认本关线索与各自真实验证按钮名称。第四城任务背景仍为透明。
- 第五城：先验证原有6/6、4/4、r43存档在跨城和整页重载后保留；正常回访缓存与监控支线，检查线索匹配与切换清除。之后明确点击本城重玩，正常完成NOOR、DB-01与DB-02，用故障簿追踪未取证DB-S1，验证先天气→偏振镜→再取证的提示。引导本身没有收集证据，也没有解锁未到过设施的沙舟。
- 键盘与手机：新提示按钮可Tab聚焦并Enter激活；Escape与原有关闭照常。手机提示按钮44px，无横向溢出，底部验证仍可达。
- 代码自审：新模块只读领域进度与已经呈现的任务/交互，不持有推进关卡的能力。提示使用textContent，未引入外部内容或依赖。面板初始化一次，只有提示变化才更新文字与描边。

实测修正了两处目标优先级问题：站在上一台已修好设备旁时，旧互动不能覆盖新任务；地下档案的首次证据判断必须针对该档案，不能因附近另一设备已经取证就跳过天气说明。相关正常UI反例已重验。

## 发布与适用边界

完成受影响UI及文档→运行verify→写入最终错误列表→源码指纹封存→release:check→再提交推送。V6.4.1有独立回执、审查文件与至少12项UI检查门槛；第五城原始85项和37张截图保留为历史功能基线，未宣称本轮重玩全部旧关卡。

当前主包约901kB（gzip261kB），CSS约97kB；原有500kB分块建议继续显示。未增加联网行为、素材和依赖。真实玩家能否更容易理解仍需继续收集反馈；本轮确认提示时机、目标、操作和持久线索可用。图文见[README引导说明](../../README.md#guidance)与[截图索引](../guide/README.md)。
