# V6 · 开发与工程说明

玩家图文玩法见[仓库首页](../../README.md)。本文中的代码路径均相对仓库根目录。

V6.4 开放指针港、脉冲炉、千线程、雨线城 · 白噪雪原、镜库城五城。三维浏览器探索与因果修复游戏，基于用户提供的 V6 设计包和第五城镜库主题继续开发。

你是零号，一个没有身份记录的城市残留体。MIRA 的女儿还在 B 站等待，列车却一直把那里跳过。你通过观察、扫描、改写有限的因果规则和重放验证，将她接回世界。

## 启动与构建

使用 Node.js 24 或更高版本。

```sh
npm ci
npm run dev -- --host 127.0.0.1 --port 5386
npm test
npm run build
npm run release:check
npm run preview -- --host 127.0.0.1 --port 5387
```

开发入口 `http://127.0.0.1:5386/`。生产入口是 `dist/index.html`，将整个 `dist/` 部署到支持 HTTPS 的静态托管服务即可。网页必须通过 HTTP(S) 访问，不能双击 HTML 以 `file://` 运行模块脚本。

正式构建不包含开发传送/模拟钩子。`window.__REFLOW__.snapshot()` 是只读诊断；`?perf=1` 显示实时测量的帧率、帧时和绘制量，不是预填数值。

## 已完成的完整一局

1. 进入真实 3D 指针港，移动、冲刺、跳跃、转动相机，找到 MIRA，取得因果织针。
2. **Q-01 事件失序**：扫描提前删除的站台；拖动事件顺序；分别验证普通和慢速旅客。失败提供可复现反例；正确排序展开有碰撞的维修桥。
3. 沿维修桥和坡道进入高架层。旁侧还可探索上层核心观景台，或步行前往失联的 B 站。
4. **DS-01 失联线路**：扫描实际遍历 `A → C → END`；拖动三维节点连线，或用键盘可聚焦的节点控件修改 `next`。实验可造成自环、漏站，均由独立模拟器判定。
5. 回归通过才提交线路。实体轨道、承重区域、车站招牌、城市窗灯、NPC 和列车停靠状态一起恢复。列车回放绑定同一 `runId` 的访问日志。
6. 在 A 站登车，经过恢复的车站，抵达 END 结算。可以留下自由探索、复制修复记录或重新开始。
7. 从首城结算、END 站、任务按钮或地图乘城际列车，进入脉冲炉，与 K-13 交谈。
8. **WF-01 晴雨供电**：晴天蓄能 → 关闭隔离闸 → 雨天散热；同时满足储能、温度和雨天保电回归，才锁存电源、展开有真实承重面的通道。
9. 沿两段坡道到八位时钟塔，扫描 **CO-01 失忆电梯**，编辑使能信号。ZERO、CARRY、POWER 的分支行为由 8 位 ALU 模型计算；完整验证覆盖 65,536 组输入。
10. 乘升降台从 26m 上升到 50m，完成第二城，搭乘城际列车前往千线程。
11. 与 IRIS 对话，完成四主线：共同锁序及受控重启、等待老化、原子或互斥计票、三页框 LRU。错误补丁产生实际执行反例，成功后逐层打开实体桥。
12. 探索两条可选故事：噪声唤醒后重查条件、CAS 取得不自动过期的独占权限。两条都可以在主线结束后补完。
13. 四主线综合回归通过后再登车，经历 18 秒双塔列车行程，到上层平台结算，再前往白噪雪原。
14. 与 KESTREL 对话，在开阔冰峡谷完成五主线：风向/风闸/恒温除冰、健康备路与 TTL、重传去重与重复 ACK、自适应窗口与退避、已知批次下的逻辑时钟与共同平局规则。每项多负载验证后才开放下一座承重桥。
15. 可选探索地址过期、CRC-8 与重传、心跳恢复与代次栅栏三段故事，均可在主线结算后补齐。
16. 五系统综合回归强制暴风雪，玩家实际稳身步行北→西→北，逐站按 E 完成三次交接。中途刷新和跌落从已交接的避风站恢复；最终交接先完成权威状态再持久化。
17. 四城支持往返和独立续玩。旧 V6.2 已通过第三城的存档自动迁移；重玩第二、第三城保留已验证的后续通行资格，资格本身也会重新校验已提交策略。

两种有效事件排序都会通过。线路也不硬编码唯一答案：只要保持全部站点唯一可达、无环，且 B 站支线正常到达终点，其他有效线路同样会被认可。返航读取实际提交的路线。

## 操作

| 操作 | PC | 手机竖屏/横屏 |
| --- | --- | --- |
| 移动 | WASD / 方向键 | 左侧摇杆 |
| 冲刺 / 跳跃 | Shift / Space | 上箭头跳跃 |
| 转动视角 | 按住右键拖动 | 右侧空白处拖动 |
| 扫描 | Q | 「溯源」 |
| 对话、断点、登车 | E | 画面中的交互提示 |
| 验证补丁 | R / 工作台按钮 | 工作台「重放并验证」 |
| 地图 | M / Tab | 右下「城市图」 |
| 天气 | T / 右上晴雨按钮 | 右上晴雨按钮 / 天气工作台 |
| 雪原抗风 | 按住 F / 稳身按钮切换 | 先点稳身，再推摇杆 |
| 暂停 / 退出编辑 | Esc | 右上暂停 / 工作台关闭 |

指针港断点编辑时局部执行冻结；脉冲炉天气工作台持续模拟设备，暂停菜单或后台失焦才冻结。错误接线草案不会提交到权威世界，也不会清空证据。无尝试次数锁定。跌落回到安全检查点。后台/失焦暂停游戏与声音，需要显式恢复。

第四城天气为晴霁、降雪、暴风雪。运动使用 60Hz 固定步长，每一步先计算风、抓地与稳身，再交给运动器；避免在一次渲染帧内重复使用错误的累积时间。避风区移除风力。编辑器中的有限环境模型独立于渲染帧，预演不提交。最终投递的天气约束同时在 UI 与领域事务中检查。

## 工程结构

- `src/game/domain.ts`：纯 TypeScript 领域模拟、不可变事件日志、断言、补丁事务、版本化存档校验。
- `src/game/forge-domain.ts`：天气电路、隔离与散热、8 位加法、完整输入空间回归、第二城存档校验。
- `src/game/forge-chapter.ts`：第二城阶段、实时工作台、快照报告、城际衔接与升降台演出。
- `src/game/pulse-world.ts`：独立铜色散热城市、位环、集电板、隔离装置和真实上行路线。
- `src/game/thread-domain.ts`：六关纯模型、有限交错与可达状态搜索、提交事务、综合回归和存档证明校验。
- `src/game/thread-layout.ts`：第三城坐标、承重面、检查点和独立世界边界。
- `src/game/thread-world.ts`：双螺旋塔、分层步道、设备执行回放、双线列车曲线与晴雨场景。
- `src/game/thread-chapter.ts`、`thread-content.ts`、`thread.css`：第三城工作台、六关任务册、站间接驳、叙事与响应式界面。
- `src/game/snow-domain.ts`：八个有限风雪/网络模型、严格参数重建、提交事务、综合回归、三站投递与存档证明。
- `src/game/snow-layout.ts`：第四城水平路线、实体冰桥、避风区、横风与稳身、交接检查点。
- `src/game/snow-world.ts`：雪原与黑岩、程序天线/避风舱/雪地车、雪粒/地吹雪/极光、现场执行显示。
- `src/game/snow-chapter.ts`、`snow-content.ts`、`snow.css`：三天气、八关维修册、勘测图、三级线索、步进回放、手动风暴投递及窄屏单列故事。
- `src/game/mirror-domain.ts`：第五城缓存、并发值守、副本选举有限模型，取证、提交、综合回归与存档校验。
- `src/game/mirror-layout.ts`、`mirror-world.ts`：镜面长廊、逐关解锁的实体光桥、安全检查点与青蓝三维场景。
- `src/game/mirror-chapter.ts`、`mirror.css`：NYX 对话、三关工作台、执行日志、镜像档案与第五城结算。
- `src/game/weather.ts`：晴雨渐变、太阳、云层、雨线与依据承重面高度定位的雨圈。
- `src/game/physics.ts`：60Hz 运动、跳跃缓冲、土狼时间、矩形承重面、斜坡、障碍和安全复位。适用于当前人工设计的场景，尚非通用物理引擎。
- `src/game/world.ts`：确定性模块城市、实例化楼体、原创建筑纹理、程序角色、实体轨道、列车、降雨与水面。
- `src/game/view.ts`：Three.js WebGL2 渲染、镜头插值、防遮挡与世界坐标投影。PC、窄窗口、手机竖屏具有不同的调试构图。
- `src/game/input.ts`：键盘、鼠标、摇杆和 Pointer Events。
- `src/game/audio.ts`：用户手势解锁的原创 Web Audio 编曲与反馈，默认静音。
- `src/game/main.ts`：任务状态、工作台、反例报告、演出、设置、暂停与结算。
- `public/character-card.html`：主角概念设定卡，明确区分 AI 概念图与实机模型。
- `tests/v6.test.ts`：新规则、事务、存档和碰撞测试；旧版 18 个测试仍保留。
- `tests/forge.test.ts`：21 项新增测试，覆盖漏电、温度边界、帧率一致性、全部加法输入、旧存档迁移与登塔碰撞。
- `tests/thread.test.ts`：33 项测试，覆盖六种规则、有效替代解、事务、伪造存档、可选任务、重玩通行资格、三段坡道和独立城市边界。
- `tests/snow.test.ts`：62 项测试，覆盖八关反例/有效替代解、CRC 独立向量、TTL 转发边界、真实模型预算、事务、伪造存档、旧存档迁移、重玩资格、跨帧率风力、冰桥跌落与全部主桥/三段最终路线。
- `tests/mirror.test.ts`：第五城反例、有效替代解、流程、旧存档迁移及实体光桥测试。
- `scripts/check-release.mjs`：文档本地链接、构建静态资产、开发工具隔离和已审核源码指纹核验。
- `.github/workflows/verify.yml`：Node 24 下干净安装并执行发布检查，仓库权限只读。
- `qa/viewport.html`：本地响应式验收画框，不纳入正式构建。

采用 Three.js 直接管理渲染，不引入 React 的逐帧状态更新。重复楼体使用 [InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html)。角色碰撞选用文档允许的轻量 kinematic controller，任务模拟与视觉帧率独立。

## 存档与隐私

游戏不接入账号、分析服务或外部 AI API。进度和设置只保存在当前浏览器的 `localStorage`；无法使用存储时仍可游玩。继续游戏会回到已完成任务对应的安全检查点，尚未提交的编辑草案会被舍弃，证据保留。清除浏览器站点数据会丢失本地存档。Sites 试玩地址的访问范围由托管权限单独控制。

发布顺序：完成代码与文档 → 运行 `npm run verify` → 正常界面回归与代码自审 → 记录最终控制台错误列表 → `node scripts/check-release.mjs --seal` → `npm run release:check` → 提交并推送。指纹记录对应所审源码；源码再变化时必须重跑受影响项、重新封存。封存命令本身不会替代界面测试或审查。GitHub CI 会重新执行同一发布检查。

当前发布检查按包版本选择独立回执与审查文件，V6.4 要求至少 25 项全部通过的 UI 记录及空的最终错误列表。指纹覆盖当前游戏源码、测试、公共资源、图文攻略、审查文档、包锁和构建/CI 配置；文本行尾归一，图片按原始二进制哈希，Windows 与 Linux 可复核。回执自身不进入指纹。

尚未实现：剩余三主城与 ROOT 终章、完整跨城依赖 DAG、战斗与钩锁、手柄、通用动态物理、全量 glTF/LOD 流送和完整剧情音轨。地图标记规划项，不声称具有 5–8 小时内容。第二至第五城按首次进入延迟构建，只渲染当前场景；场景缓存供往返使用，尚未实现全量城市流送。Vite 构建仍提示 500 kB 分块建议，未关闭该提示。

老项目主入口保留在 `legacy-v5.html`，代码仍在 `src/main.ts`、`src/v5/`，旧说明保留在 `docs/v6/LEGACY_V5_README.md`。正式首页改为 V6；正式构建只打包 V6。
